> 상태: `docs/implementation-plan.md` 및 `contracts/pds-schema-v2.json` 기준 최신화 완료. 브라우저용 Firestore SDK 직접 연결 및 Firebase Hosting 정적 웹 아키텍처를 전제로 평가를 진행합니다.

## 1. 아키텍처 및 배포 기준

| 영역 | 확정 기술 규격 | 판단 근거와 주의점 |
|---|---|---|
| 프런트엔드/앱 | 정적 Single Page Application (SPA) | 브라우저 상에서 동작하는 정적 번들입니다. |
| 데이터베이스 | Cloud Firestore (Native mode) | 실제 서버 데이터베이스입니다. 브라우저용 Firebase SDK v9+ modular를 통해 직접 읽기/쓰기를 수행합니다. |
| 배포 | Firebase Hosting | 정적 웹 호스팅 제품입니다. 별도 Node.js 서버 런타임 없이 동작합니다. |
| DB 접근 및 보안 | 브라우저 Firestore SDK 직접 연결 + Firestore Security Rules | 관리자 키(Admin SDK)를 절대 번들에 포함하지 않습니다. 공개 앱 특성상 Firestore Security Rules를 통해 스키마 무결성과 악성 필드 주입을 방어합니다. |

**로그인 없는 공개 앱의 한계:** 
로그인이 없으므로 링크를 아는 누구나 읽기 및 쓰기 작업을 할 수 있습니다. 따라서 민감한 개인정보나 타인의 정보는 입력하지 않으며, 첫 화면 표지에 다음 문구를 반드시 노출합니다:
> "지금은 로그인이 없어 링크를 아는 사람은 누구나 볼 수 있습니다. 남이 봐도 괜찮은 내용만 넣으세요"

## 2. 데이터 및 동작 기준

세부 데이터 계약은 [`contracts/pds-schema-v2.json`](../contracts/pds-schema-v2.json)을 따릅니다.

- **계획 수정**: 현재 계획 문서의 ID는 유지하고, 수정 직전 값을 `planRevisions` 컬렉션에 불변 스냅샷으로 저장합니다. 스냅샷 생성과 계획 문서 갱신은 단일 Firestore `runTransaction`으로 원자적 처리합니다.
- **할 일과 실행 기록 연결**: 할 일은 `planId`로 계획에 연결되고, 실행 기록은 `planId` 및 `taskId`로 연결됩니다.
- **중복 완료 방지 (T06-C21)**: 할 일 완료 시 Firestore `runTransaction` 내에서 대상 할 일의 현재 `status`를 조회하여 이미 `done`인 경우 트랜잭션을 조기 종료(no-op)합니다. 이를 통해 네트워크 지연이나 연속 클릭 시에도 단 1건의 상태 전이 및 1회의 `completedAt`만 기록됩니다.
- **돌아보기 (T06-C81)**: 선택한 캘린더 날짜 범위(KST 기준)와 매칭되는 계획, 완료된 할 일, 실행 기록을 집계합니다. 집계 숫자를 클릭하면 해당 집계 대상 기록의 상세/필터링 화면으로 즉시 이동합니다.
- **검색·거르기·정렬 (T06-C18 ~ C20)**: 화면 상단에 정렬 기준을 명시하고, 동률 발생 시 4차 정렬 키(`id` 오름차순)를 적용하여 비결정적 순서 변동을 차단합니다.
- **휴지통 및 삭제 (T06-C13)**: 3단계 상태값(`0=존재, 1=휴지통, 2=복구`)을 사용하며, 휴지통(`1`) 상태의 할 일은 기본 활성/예정 목록에서 즉시 숨겨져 T06-C13을 만족합니다.
- **시간 및 날짜 규약**: 기간·마감일은 KST 기준 문자열, 실행 기록 시각은 UTC Timestamp로 저장하고 화면에는 `YY.MM.DD HH:mm (KST)`로 변환 출력합니다.

## 4. 최종 제출 직전 기록 양식

### 재현·통과 확인 4가지
- **어디로 가나요**: `https://<firebase-project-id>.web.app`
- **무엇을 하나요 (3단계 이내)**:
  1) 첫 화면 다이어리 표지(경고문 및 열린 잠금쇠)를 확인하고 다이어리를 열어 돌아보기 및 계획을 확인한다.
  2) 실제 등록된 계획의 할 일 목록에서 할 일을 완료하거나 실행 기록을 추가한다.
  3) 돌아보기 탭에서 갱신된 집계 숫자를 누르고 해당 상세 기록으로 이동되는지 확인한 뒤 전체 데이터를 JSON으로 내보낸다.
- **무엇이 보이면 통과인가요**: 새로고침 후에도 실제 입력한 계획·할 일·기록이 유지되고, 집계 숫자 클릭 시 해당 목록으로 연결되며, 내보낸 JSON에 ID와 값이 완전하게 포함되어 있을 때
- **안 될 때는 무엇이 보이나요**: 데이터 저장이 되지 않고 에러 안내(커피 쏟아진 연출 등)가 표시되거나, 새로고침 시 입력값이 유실될 때

### AI와 내 판단 3줄
- **AI에게 맡긴 일**: 다이어리 스큐어모피즘 UI 컴포넌트 구현 및 Firestore 브라우저 SDK CRUD/트랜잭션 보일러플레이트 작성
- **내가 직접 판단한 일**: 실제 수행 중인 계획·할 일·실행 기록 데이터 선정 및 브라우저 SDK 직접 연결에 따른 비인증 Security Rules 보안 경계 설정
- **AI 말을 안 들은 일**: (실제 작업 시 AI가 제안했으나 기각한 항목과 그 기술적 이유를 기입)
