# T06 과제 요구사항 충족 검증 체크리스트 (Verification Checklist)

> 본 문서는 과제 6(플랜두씨 다이어리 1)의 모든 통과 기준(T06-C01 ~ T06-C82), 제출 제약, 아키텍처 결함 및 기존 계획 문서(`docs/evaluation-plan.md`, `docs/implementation-plan.md`, `contracts/pds-schema-v2.json`)와의 정합성을 기계적으로 대조·검증하기 위해 작성된 단일 진실 공급원(Single Source of Truth) 체크리스트입니다.

## 1. 아키텍처 확정 사항 및 M0 문서 최신화 요건 (Single Source of Truth: `implementation-plan.md`)

`implementation-plan.md`가 최신 확정 기준(Single Source of Truth)이며, `docs/evaluation-plan.md`와 `contracts/pds-schema-v2.json`은 초기 제안본으로 M0 단계에서 `implementation-plan.md`에 맞춰 최신화되어야 합니다.

| 식별 번호 | 검토 및 최신화 항목 | `implementation-plan.md` 확정 기준 | 과거 초안(`evaluation-plan.md` / `schema`) 잔재 및 조치 | 위험도 및 조치 필요사항 |
|---|---|---|---|---|
| **S-01** | **백엔드 아키텍처** | **Firebase Hosting 정적 웹 + 브라우저용 Firestore SDK 직접 연결** (서버 없음) | `evaluation-plan.md`의 Next.js App Router + App Hosting + Admin SDK 서버 API 잔재 제거 필요 | **M0 반영 필수**. `evaluation-plan.md`를 브라우저 SDK 직접 연결 및 Firestore Security Rules 기반으로 최신화. |
| **S-02** | **T06-C21 동시성/멱등성 제어** | 브라우저 SDK의 Firestore 트랜잭션(`runTransaction`) 사용 | 서버 API의 Idempotency-Key 잔재 정리 | **검증 주의**. 브라우저 SDK 트랜잭션 내에서 할 일의 현재 완료 상태(`completedAt`, 상태 플래그)를 확인 후 원자적 갱신하여 중복 완료 방지. |
| **S-03** | **T06-C81 집계 클릭 네비게이션** | 완료 수(완료된 할 일 목록 이동) 외 나머지 집계 대상 확정 필요 | 과제 필수 기준: "집계 숫자를 눌러 그 숫자가 나온 기록으로 갈 수 있다" | **M0 반영 필수**. 계획 수(기간 내 계획 목록), 실행 기록 수(기록 목록), 시간 차이(차이 산출 대상 할 일 목록)의 네비게이션 타깃 명시. |
| **S-04** | **T06-C20 정렬 및 동률 처리** | 마감일 빠른 순 -> 우선순위 높은 순 -> 가나다순 | 세 정렬 값 동일 시 마지막 순서 미정 | **M0 반영 필수**. 동률 발생 시 고유 키(`taskId` 오름차순)를 화면과 코드에 확정하여 비결정적 정렬 차단. |
| **S-05** | **휴지통 및 삭제 규칙** | 3단계 상태(`0=존재, 1=휴지통, 2=복구`), 7일 복구, 종속 삭제 | T06-C13: 할 일 삭제 및 새로고침 후 미노출 | **규격 확인**. 휴지통(`1`) 또는 삭제 상태의 데이터가 일반 목록 및 돌아보기 기본 집계에서 제외되는지 검증. |

## 2. 세부 통과 기준 매트릭스 (T06 Compliance Matrix)

| 기준 ID | 과제 통과 기준 | 검증 절차 및 입력값 | 기대 결과 (PASS 판정 조건) | 증거 수집 대상 |
|---|---|---|---|---|
| **T06-C04** | 계획에 기간이 저장된다. | 계획 생성/수정 시 시작일(`YYYY-MM-DD`)과 종료일(`YYYY-MM-DD`) 입력 후 저장 | 새로고침 후 입력한 기간이 변형 없이 표시되고, DB에 동일 날짜 저장 확인 | 계획 화면 스크린샷, DB 문서 필드 확인 |
| **T06-C05** | 계획에 우선순위가 저장된다. | 우선순위(높음/보통/낮음 등 정의된 규격) 지정 후 저장 | 새로고침 후 설정한 우선순위 유지 및 DB 필드 일치 | 계획 화면 스크린샷, DB 문서 필드 확인 |
| **T06-C06** | 계획에 성공 기준이 저장된다. | 성공 기준 텍스트 입력 후 저장 | 새로고침 후 텍스트 손실/왜곡 없이 렌더링, DB 필드 일치 | 계획 화면 스크린샷, DB 문서 필드 확인 |
| **T06-C07** | 계획에 예상 시간이 저장된다. | 예상 시간(분 단위 정수) 입력 후 저장 | 화면에 단위(분 또는 시간)와 함께 정확히 표시되며 DB 저장값과 일치 | 계획 화면 스크린샷, DB 문서 필드 확인 |
| **T06-C08** | 계획을 고쳐도 고치기 전 계획이 그대로 남아 있다. | 기존 계획의 기간, 우선순위, 성공 기준 수정 후 저장 | 계획 문서의 ID는 유지되되, 수정 전 스냅샷이 별도 revision 컬렉션/테이블에 불변으로 보존되고 화면 이력 탭/취소선으로 확인 가능 | 수정 전/후 화면 캡처, DB revision 레코드 확인 |

| **T06-C78** | 내가 실제로 세운 계획이 하나 이상 들어 있다. | DB 및 화면 상의 계획 실데이터 확인 | 가짜/더미/템플릿이 아닌 실제 수행 중인 계획 1개 이상 존재 | 계획 화면 캡처 |
| **T06-C79** | 그 계획에 딸린 할 일이 다섯 개 이상 들어 있다. | 계획 하위 할 일 개수 카운트 | 실제 할 일 최소 5개 이상 등록 및 확인 | 할 일 목록 화면 캡처 |
| **T06-C80** | 실제로 한 일 기록이 세 개 이상 들어 있다. | 할 일 하위 실행 기록 개수 카운트 | 실제 실행 기록 최소 3개 이상 등록 및 확인 | 실행 기록 화면 캡처 |

| **T06-C82** | 첫 화면에 지정된 공개 경고 안내문이 정확히 적혀 있다. | 첫 화면 진입 시 문구 대조 | `"지금은 로그인이 없어 링크를 아는 사람은 누구나 볼 수 있습니다. 남이 봐도 괜찮은 내용만 넣으세요"` 토씨 하나 틀리지 않고 렌더링 | 첫 화면 안내문 캡처 |

## 3. 최종 제출물 자격 요건 검증표 (Pre-Submission Gate)

제출 버튼을 누르기 전 체크해야 하는 필수 형식 요건입니다.

```
[ ] 1. 공개 결과물 URL
    - 형식: https://<project-id>.web.app 또는 https://<custom-domain>
    - 검증: 시크릿 창(인증/로그인 없음)에서 첫 화면 및 데이터 정상 렌더링 확인

[ ] 2. 소스 저장소 URL
    - 형식: https://github.com/<owner>/<repo>/commit/<40-or-64-char-hex-hash>
    - 검증: 브랜치 메인이 아닌 전체 커밋 해시가 포함된 영구 링크 확인

[ ] 3. 스키마 계약 파일 포함 여부
    - 경로: contracts/pds-schema-v2.json
    - 검증: 최종 DB 구조, 엔티티 간 관계, 타임존/날짜 포맷 규약 반영 여부

[ ] 4. 재현·통과 확인 4줄 작성 상태
    - 어디로 가나요: [URL]
    - 세 단계 안에 무엇을 하나요:
      1) ...
      2) ...
      3) ...
    - 무엇이 보이면 통과인가요: [정상 케이스]
    - 안 될 때는 무엇이 보이나요: [오류 케이스]

[ ] 5. AI와 내 판단 3줄 작성 상태
    - AI에게 맡긴 일: [구체적 명시]
    - 내가 직접 판단한 일: [구체적 명시]
    - AI 말을 따르지 않은 일: [구체적 사유 명시]
```
