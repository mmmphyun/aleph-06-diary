# T06 구현 계획 — 마일스톤 기반

> **상태:** 요구사항·진행 순서 초안. 앱 구현, Firebase 설정, 배포, 실제 데이터 검증은 아직 하지 않았습니다.  
> **작성 원칙:** 대화에서 확정된 내용과 아직 정하지 않은 내용을 분리합니다. 열린 질문은 구현자가 임의로 결정하지 않습니다.  
> **일정:** 기간·담당자·공수는 정해지지 않아 기입하지 않습니다.

## 1. 진행 방식

마일스톤은 달력상의 주차나 화면 목록이 아니라 **사용자가 확인할 수 있는 결과와 통과 증거**를 기준으로 나눕니다. 각 마일스톤에는 목적, 작업 범위, 완료 조건, 연결된 T06 기준을 둡니다. 한 마일스톤은 기능이 만들어진 것만으로 완료 처리하지 않고, 저장·새로고침·화면 결과 등 해당 조건의 증거까지 확인한 뒤 완료 처리합니다.

권장 순서는 다음과 같습니다.

1. 남은 설계 질문을 닫고 기술 계약을 현재 결정에 맞게 고칩니다.
2. 다이어리의 화면 뼈대를 만듭니다.
3. 계획과 수정 이력을 실제 Firestore에 연결합니다.
4. 할 일의 작성·수정·검색·필터·정렬을 연결합니다.
5. 실행 기록과 중복되지 않는 완료 처리를 연결합니다.
6. 달력 기반 돌아보기와 집계의 상세 이동을 연결합니다.
7. 휴지통·복구·만료·내보내기를 연결합니다.
8. 본인의 실제 자료를 넣고 공개 배포와 제출 증거를 확인합니다.

## 2. 현재까지 확정된 제품·데이터 방향

### 기술·공개 범위

- 데이터베이스는 **Cloud Firestore**로 정하고 Realtime Database 대신 사용합니다.
- **Firebase Hosting 정적 웹 + 브라우저용 Firestore SDK 직접 연결**로 진행합니다. T06에는 별도 서버 기능을 두지 않습니다.
- T06에는 로그인이 없습니다. 공개 범위를 전제로 하며, 민감한 내용은 넣지 않습니다. 브라우저 직접 연결에서는 Firestore Security Rules가 실제 권한 경계이고, 클라이언트 쪽 검사만으로 데이터 쓰기를 막을 수 없습니다. 인증 없는 규칙으로 허용한 읽기·쓰기 작업은 방문자가 호출할 수 있습니다.
- T06과 T07은 한 저장소, 같은 Firebase 프로젝트·DB, 같은 공개 결과물 URL을 이어 쓰는 방향입니다. T07 요구사항을 확인한 뒤 이 운영 결정을 다시 검토할 수 있습니다. T06 제출 상태는 최종 전체 커밋으로 고정해 보존해야 합니다.
- 프런트엔드 프레임워크·빌드 도구, Firebase 프로젝트·리전·요금 설정은 아직 확정되지 않았습니다. 브라우저에 관리자 키나 서비스 계정 비밀값을 넣지 않습니다.

### 다이어리 화면과 연출

- 첫 화면은 다이어리 표지입니다. 로그인 없음은 이모지가 아닌 **실물 다이어리 잠금쇠가 열린 그림**으로 나타냅니다.
- 잠금쇠에 붙인 메모지에 다음 문구를 그대로, 읽을 수 있게 표시합니다.

  > 지금은 로그인이 없어 링크를 아는 사람은 누구나 볼 수 있습니다. 남이 봐도 괜찮은 내용만 넣으세요

- 다이어리를 열었을 때 첫 내지는 돌아보기입니다. 날짜 범위를 고르는 달력은 돌아보기 페이지 안에 둡니다.
- 검색·필터·정렬은 필요한 페이지에 해당하는 인덱스 메모지로 표현하고, 페이지마다 조작과 상태를 분리합니다. 돌아보기의 날짜 달력은 인덱스 메모지가 아닙니다.
- 빈 상태는 깨끗한 빈 페이지, 실제 저장 중은 펜으로 쓰는 연출, 오류는 커피가 쏟아진 페이지와 읽기 쉬운 오류 메시지로 표현합니다. 저장이 끝나기 전에 성공한 것처럼 보이게 해서는 안 됩니다.
- 계획 수정 이력은 모두 보존합니다. 화면에는 수정 전 값을 취소선으로 남기고, 여러 이력은 페이지당 5개씩 넘겨 보는 안을 사용합니다.
- 할 일 상태는 진행 전·진행 중·완료를 서로 다른 색의 스티커로 표시합니다. 색상 자체는 미정입니다.
- 삭제는 페이지를 찢는 연출, 복구한 항목은 구겨진 종이와 테이프 연출로 나타냅니다.

### 계획·할 일·실행 기록

- 계획에는 ID, 기간, 우선순위, 성공 기준, 예상 시간을 담습니다. 계획 내용을 수정해도 계획 ID는 유지하고, 수정 직전의 전체 계획 값을 별도 이력으로 보존합니다. 계획 제목 필드는 아직 정하지 않았습니다.
- 할 일은 계획에 연결합니다. 실제 본인의 계획·할 일을 입력하며, 완료 제출 자료에는 계획 1개 이상, 할 일 5개 이상, 실행 기록 3개 이상이 필요합니다.
- 할 일에는 사용자가 정하는 시작일, 필수 마감일, 우선순위, 태그, 예상 시간과 상태가 필요합니다. 새 할 일 시작일은 오늘(KST), 마감일은 시작일에서 7일 뒤의 **23:30(KST)**로 기본 입력합니다. 마감일은 필수입니다.
- 계획과 할 일의 우선순위는 **높음 → 보통 → 낮음** 순입니다. 예상 소요 시간은 30분 단위로 입력합니다. 실제 시각 값은 UTC로 저장하고 화면에는 KST로 표시합니다. 마감 시각은 24시간제이며, 시각 표시 형식은 `YY.MM.DD HH:MM`입니다.
- 할 일 검색은 제목과 설명을 대상으로 합니다. 태그는 검색 대상이나 고정 화이트리스트가 아니라 별도 태그 아카이브로 다룹니다. 필터 조건은 상태·우선순위·마감일이며 태그 필터는 두지 않습니다. 필터를 동시에 적용하는 결합 방식은 아직 정하지 않았습니다.
- 예정 목록의 기본 범위는 한국 시간 기준 오늘부터 다음 달 같은 날짜까지입니다. 대상은 사용자가 시작일을 설정한 미완료 할 일입니다. 완료 목록의 기본 범위는 지난달 같은 날짜부터 오늘까지이며, 현재 완료 상태이고 `completedAt`이 그 기간에 들어오는 할 일입니다. 더 오래된 기간도 날짜 범위를 바꿔 찾을 수 있게 합니다.
- 예정 목록 정렬은 마감일 빠른 순 → 우선순위 높은 순 → 제목 가나다순입니다. 완료 목록은 완료 시각 최신 순입니다. 세 정렬 값까지 모두 같은 항목의 마지막 순서는 아직 정하지 않았습니다.
- 한 할 일에 실행 기록 여러 개를 연결할 수 있습니다. 실행 기록에는 시작·종료 시각과 막혔던 이유를 남기고, 실제 소요 시간은 시작·종료 시각으로 계산합니다. 실행 기록 저장은 계획 값을 덮어쓰지 않습니다.
- 할 일이 완료 상태가 되면 `completedAt`을 저장하고, 진행 중으로 되돌리면 비웁니다. 재완료 시에는 새 완료 시각을 기록합니다. 완료 집계는 선택 기간의 `completedAt`을 가진 **현재 완료 상태의 할 일**을 세며, 완료 취소된 항목은 완료로 세지 않습니다.

### 돌아보기·휴지통·내보내기

- 돌아보기 기간은 날짜 범위이며 시각 단위로 자르지 않습니다.
- 계획 수는 선택 기간과 기간이 겹치는 계획을 셉니다.
- 완료 수는 현재 완료 상태인 할 일의 `completedAt` 기준입니다.
- 실행 기록 수는 계획일 기준으로 집계한다는 방향이 정해졌습니다. 계획일을 할 일 시작일과 연결하는 세부 규칙, 시작일이 바뀐 경우의 과거 집계 방식은 아직 정하지 않았습니다.
- 시간 차이는 `실제 시간 - 예상 시간`입니다. 한 할 일에 연결된 실행 시간은 합산합니다. 평균은 완료된 할 일 중 예상 시간이 있고 종료된 실행 기록이 있는 항목만 포함하며, 할 일별 차이를 평균합니다.
- 완료 수를 누르면 완료된 할 일 목록을 보여 줍니다. 나머지 집계 숫자의 상세 이동 조건은 아직 정하지 않았습니다.
- 휴지통 플래그는 `0=존재`, `1=휴지통`, `2=복구`입니다. 복구 기본값은 `2`이며, 사용자가 원하면 `0`으로 바꿀 수 있습니다.
- 계획을 휴지통에 넣으면 연결된 할 일·실행 기록·계획 수정 이력도 함께 이동합니다. 할 일을 휴지통에 넣으면 그 할 일과 실행 기록을 함께 이동합니다. 실행 기록만 휴지통에 넣는 것도 가능합니다.
- 휴지통에 넣은 시각부터 7일 동안 복구할 수 있고, 복구하면 만료 시각을 없애며 다시 휴지통에 넣으면 새로 7일을 계산합니다. 만료 시각이 지난 자료는 앱에서 복구할 수 없게 하고 Firestore에서 실제 삭제합니다. Firestore TTL 삭제는 만료 시각에 정확히 실행되는 것이 아니며, 서로 다른 문서로 저장한 연결 자료는 각각 만료 처리가 필요합니다.
- 전체 자료는 ID를 포함한 UTF-8 JSON 파일 하나로 내보냅니다. 내보내기에 비밀값은 포함하지 않습니다. 휴지통 자료를 내보낼지 여부는 아직 정하지 않았습니다.
- 사용자가 입력한 문자열은 HTML로 실행하지 않고 텍스트 그대로 표시합니다.

## 3. 마일스톤과 완료 조건

### M0 — 결정 마감 및 문서 계약 정리

**목적:** 구현자가 데이터 의미나 화면 동작을 추측하지 않아도 되도록 열린 질문을 닫습니다.

**작업:**
- 아래 열린 질문 중 데이터 모델·집계·기본 목록에 영향을 주는 항목을 결정합니다.
- `contracts/pds-schema-v2.json`을 브라우저 Firestore 직접 연결, 현재 우선순위, 날짜·시각, 완료 집계, 휴지통 규칙에 맞게 갱신합니다.
- `docs/evaluation-plan.md`의 과거 기술·동작 제안도 현재 선택에 맞게 정리합니다.
- Firebase Hosting·Firestore의 프로젝트 위치, TTL 설정 가능 여부, 실제 요금·무료 한도를 Firebase 콘솔에서 확인합니다. 무료 사용량은 무제한으로 전제하지 않습니다.

**완료 조건:** 스키마와 평가 계획표가 서로 모순되지 않고, 열린 질문이 남아 있더라도 각 질문이 구현 범위 밖으로 명시적으로 보류되어 있습니다. 프런트엔드 도구와 Firebase 운영 설정도 확정 또는 보류 상태가 문서에 드러납니다.

**연결 기준:** 준비 단계. 이 문서만으로 Firebase 프로젝트 생성이나 배포가 완료된 것으로 보지 않습니다.

### M1 — 다이어리 표지와 페이지 골격

**목적:** 앱을 다이어리처럼 열고 넘길 수 있는 화면의 기반을 만듭니다.

**작업:**
- 표지, 열린 잠금쇠와 필수 안내 메모, 다이어리 열기·페이지 이동을 구현합니다.
- 첫 내지를 돌아보기로 두고, 할 일 페이지 등 필요한 페이지에만 해당 인덱스 메모지를 둡니다.
- 빈 페이지·저장 중·오류 상태의 시각 규칙을 구현합니다. 오류 메시지는 가려지거나 읽을 수 없는 장식에 묻히지 않게 합니다.
- 페이지 전환과 메모지의 시각 표현을 재사용하되, 서로 다른 페이지의 데이터 조작 상태는 섞지 않습니다.

**완료 조건:** 첫 화면에 안내 문구가 보이고, 페이지를 오가며 현재 페이지에 맞는 조작을 확인할 수 있습니다. 로딩·빈 상태·오류 상태가 서로 구별됩니다.

**연결 기준:** T06-C82 (최종 공개 전 재확인).

### M2 — 계획 작성·수정·이력

**목적:** 계획이 실제 Cloud Firestore에 저장되고, 수정 전 내용이 남게 합니다.

**작업:**
- 확정한 계획 필드로 계획을 만들고 다시 불러옵니다.
- 기존 계획을 수정할 때 ID를 유지하고, 수정 직전의 전체 값을 불변 이력으로 남깁니다.
- 이력은 취소선 연출로 확인하고, 여러 이력은 페이지당 5개씩 탐색합니다.
- 저장 성공·실패에 맞춰 펜·오류 연출을 연결합니다.

**완료 조건:** 새로고침 뒤 같은 계획 ID·날짜·값·단위가 복원됩니다. 수정 뒤 현재 값과 수정 전 스냅샷이 각각 확인됩니다.

**연결 기준:** T06-C04–C08, T06-C34–C35 중 계획 저장 부분.

### M3 — 할 일 작성·수정·탐색

**목적:** 계획에 연결된 할 일을 실제 자료에 맞게 다룹니다.

**작업:**
- 할 일 생성·수정과 필수 값 검증을 구현합니다.
- 시작일·마감일 기본값, 우선순위, 태그, 예상 시간과 상태를 저장합니다.
- 제목·설명 검색, 태그 아카이브, 상태·우선순위·마감일 필터, 화면에 공개한 기준에 맞는 정렬을 구현합니다.
- 예정 목록은 할 일의 시작일로 앞으로 한 달 범위를 정하고, 마감일 → 우선순위 → 가나다순으로 정렬합니다. 동일한 값이 모두 겹칠 때의 마지막 순서는 M0에서 확정합니다.
- 진행 전·진행 중·완료 스티커를 표시합니다. 상태 전환의 데이터 규칙은 M4와 함께 검증합니다.

**완료 조건:** 할 일을 만들고 수정한 값이 새로고침 뒤 유지됩니다. 검색·필터·정렬 결과가 문서에 표시한 기준과 일치합니다.

**연결 기준:** T06-C09–C10, T06-C14–C20. 삭제·복구는 M6에서 확인합니다.

### M4 — 실행 기록과 원자적인 완료 처리

**목적:** 계획과 분리된 실제 실행 기록을 남기고, 완료 요청 중복으로 집계가 부풀지 않게 합니다.

**작업:**
- 한 할 일에 실행 기록 여러 개를 연결합니다.
- 시작·종료 시각, 계산된 실제 소요 시간, 막혔던 이유를 저장·표시합니다.
- 로그 저장 전후 계획 값이 바뀌지 않는지 확인합니다.
- 완료·진행 중 복귀·재완료 흐름을 구현합니다. 연속 완료 요청은 UI 버튼 잠금에만 의존하지 않고 Firestore 트랜잭션 등 저장 계층에서 중복 상태 전환을 막습니다.
- 완료 수는 완료 상태와 `completedAt`을 기준으로 계산하며, 완료를 취소하면 해당 완료 집계에서 빠지는지 확인합니다.

**완료 조건:** 실행 기록이 올바른 할 일에 연결되고, 같은 완료 명령을 연달아 보내도 완료 결과와 집계가 한 번만 반영됩니다. 실행 기록 저장으로 계획·수정 이력이 변하지 않습니다.

**연결 기준:** T06-C11–C12, T06-C21–C27.

### M5 — 달력 기반 돌아보기와 기록 상세 이동

**목적:** 실제 자료를 날짜 범위로 집계하고, 숫자를 만든 자료를 열어 볼 수 있게 합니다.

**작업:**
- 돌아보기 페이지에 날짜 범위 달력을 둡니다. 필터는 날짜 단위로 적용합니다.
- 계획 수, 완료 할 일 수, 실행 기록 수, 예상 대비 실제 시간 차이 평균을 계산합니다.
- 계획 수는 선택 기간과 겹치는 계획, 완료 수는 선택 기간에 완료된 현재 완료 상태의 할 일, 실행 기록 수는 M0에서 확정한 계획일 규칙을 사용합니다.
- 평균 차이는 완료된 할 일별로 연결된 실행 기록 시간을 합산한 뒤 예상 시간을 빼고 평균냅니다.
- 완료 수를 누르면 완료된 할 일을 보여 줍니다. 다른 집계 숫자의 상세 페이지도 M0에서 정한 연결 규칙을 따릅니다.

**완료 조건:** 표시 숫자가 원본 자료로 재계산할 수 있고, 집계 숫자마다 해당 숫자를 만든 필터 결과로 이동합니다. 실제 데이터로 화면이 채워지는지는 M7에서 확인합니다.

**연결 기준:** T06-C81 및 집계 숫자 이동 요구사항.

### M6 — 휴지통·복구·만료와 전체 내보내기

**목적:** 잘못 삭제한 연결 자료를 복구하고, 보존 기간이 지난 자료는 실제로 제거하며, 전체 자료를 파일로 보관합니다.

**작업:**
- `0/1/2` 휴지통 상태와 계획·할 일·실행 기록의 연결 삭제 단위를 구현합니다.
- 복구 시 연결 단위 전체를 복구하고 기본 상태를 `2`로 표시합니다. 사용자가 `0`으로 바꿀 수 있게 합니다.
- 휴지통 진입 후 7일 동안 복구할 수 있게 하고, 만료 뒤 Firestore 문서가 실제 삭제되는지 확인합니다. TTL의 비동기 삭제 특성과 연결 문서별 만료 설정을 고려합니다.
- 계획·수정 이력·할 일·실행 기록 등 전체 자료를 ID와 날짜·단위를 보존한 JSON 한 파일로 내보냅니다.

**완료 조건:** 휴지통·복구 상태가 새로고침 뒤 유지되고, 만료 자료의 실제 삭제와 내보낸 파일의 자료 범위를 확인합니다.

**연결 기준:** T06-C13, T06-C36.

### M7 — 실제 자료 입력·공개 배포·제출 확인

**목적:** 과제의 실제 사용 자료와 공개 URL을 최종 기준으로 검증합니다.

**작업:**
- 사용자가 직접 실제 계획 1개 이상, 연결된 실제 할 일 5개 이상, 실제 실행 기록 3개 이상을 입력합니다. AI가 예시 자료를 만들지 않습니다.
- 돌아보기 집계가 실제 자료로 채워지고 0만 표시되지 않는지 확인합니다.
- 새로고침 전후 ID·날짜·값·단위, Firestore 저장 내용, JSON 내보내기를 대조합니다.
- 스크립트 모양 문자열이 문자 그대로 표시되는지 확인합니다.
- 최종 소스·배포 파일·네트워크 응답·콘솔·Git 기록에서 비밀값 원문이 노출되지 않는지 점검합니다.
- 공개 결과물 URL과 전체 커밋 해시가 든 소스 URL을 새 시크릿 창에서 확인하고, 제출용 확인 방법 4항목과 AI·내 판단 3항목을 작성합니다.

**완료 조건:** 로그인 없이 열린 공개 화면과 공개 안내, 실제 Firestore 자료, 실제 자료 기반 집계, 내보내기 및 제출 증거가 모두 확인됩니다. 실제로 확인하지 않은 항목은 통과로 표시하지 않습니다.

**연결 기준:** T06-C01, T06-C34–C36, T06-C57–C60, T06-C78–C82.

## 4. 확정된 설계 결정 및 잔여 확인 항목

아래 1–5번 및 프런트엔드 도구는 사용자 결정에 따라 확정되었습니다.

1. **실행 기록 집계의 기준일 (확정 - 옵션 B):**
   - 실행 기록의 물리적 시작 일시인 `startedAt`(KST 환산 날짜)을 기준으로 돌아보기 캘린더 범위와 매칭하여 집계합니다.
2. **실제 시간 저장 및 분 단위 처리 (확정 - 옵션 B):**
   - 시작 시각(`startedAt`)과 끝난 시각(`endedAt`) 타임스탬프를 DB에 영구 저장하며, 실제 소요 시간은 클라이언트 런타임에서 `(endedAt - startedAt)`으로 계산하여 분/시간 단위로 출력합니다. (계산 가능한 원천 데이터 저장을 통해 T06-C25 충족).
3. **완료 중복 방지 자료 모델 (확정 - 옵션 A):**
   - 별도의 `completionEvents` 컬렉션을 생성하지 않고, `tasks` 단일 문서 내에서 `runTransaction`을 통해 `status === 'done'` 여부를 확인하여 멱등적(Idempotent)으로 1회의 완료 상태(`completedAt`)만 갱신합니다.
4. **필터 결합 방식 및 동률 4차 정렬 키 (확정 - 권장 규격):**
   - 상태·우선순위·마감일 필터가 복수 선택될 경우 **AND 조건**으로 결합합니다.
   - 정렬 우선순위: 1차(마감일 오름차순) → 2차(우선순위: 높음>보통>낮음) → 3차(제목 가나다순) → **4차(`id` 문자열 오름차순)**으로 완전 결정적 정렬을 보장합니다.
5. **돌아보기 집계 숫자 클릭 네비게이션 타깃 (확정 - 권장 규격):**
   - 계획 수: 해당 기간에 걸친 '필터링된 계획 목록 뷰'로 이동.
   - 완료 수: 해당 기간에 완료된 '완료 할 일 목록 뷰'로 이동.
   - 실행 기록 수: 해당 기간에 기록된 '실행 기록 타임라인 뷰'로 이동.
   - 시간 차이: 차이 계산 대상 할 일들의 '계획 vs 실제 시간 대조 뷰'로 이동.
6. **계획 제목과 태그 (확정):**
   - 계획 제목(`title`) 필드는 필수(1~120자)입니다. 태그는 선택사항(0개 이상)으로 처리합니다.
7. **내보내기 범위 (확정):**
   - 전체 JSON 내보내기 시 휴지통 데이터(`trashStatus: 1`)를 포함하여 백업의 완전성을 보장합니다.
8. **프런트엔드 도구 (확정):**
   - `Vite + React (TypeScript) + Tailwind CSS` 정적 SPA 스택으로 확정합니다.

## 5. 문서 정합성 주의

현재 `docs/evaluation-plan.md`와 `contracts/pds-schema-v2.json`은 초기 제안 상태입니다. 두 파일에는 현재 결정과 다른 Next.js/App Hosting·서버 전용 Admin SDK·정수 우선순위 4단계·논리 삭제·완료 이벤트 집계 등 과거 설계가 남아 있습니다. 따라서 이 파일들을 현재 구현 지시로 사용하지 말고, M0에서 이번 계획과 열린 질문에 맞춰 함께 갱신해야 합니다.

이 문서는 계획을 기록한 것이며, 앱 구현·서비스 설정·실제 DB 저장·브라우저 확인·테스트 통과를 의미하지 않습니다.
